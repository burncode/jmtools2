建议采用 本地项目文件 + SQLite 索引数据库 + 元数据 JSON 的混合架构。

1. 总体原则

你的软件最好是：

本地优先
项目独立
资源可迁移
导出可复现
后期可接云同步

不要一开始就做重云端数据库，否则复杂度会暴涨。

2. 推荐项目目录结构
MyAssetProject/
├─ project.json              # 项目基础配置
├─ project.db                # SQLite 索引数据库
├─ assets/                   # 正式素材
│  ├─ characters/
│  ├─ scenes/
│  ├─ items/
│  ├─ ui/
│  ├─ effects/
│  └─ audio/
├─ generated/                # AI 原始生成结果
├─ edited/                   # 编辑后的素材
├─ thumbnails/               # 缩略图缓存
├─ exports/                  # 导出结果
├─ cache/                    # 临时缓存
└─ history/                  # 版本快照，可选
3. 数据分层
文件系统存大文件

存：

png
aseprite
gif
json
wav
fbx
tileset
sprite atlas
SQLite 存索引

存：

素材 ID
名称
类型
路径
标签
尺寸
状态
创建时间
修改时间
导出状态
生成参数
JSON 存项目配置

存：

项目名称
目标引擎
默认像素尺寸
默认调色板
导出规则
目录规则
命名规范
4. 核心数据模型

建议统一为 Asset：

Asset {
  id: string
  name: string
  type: "character" | "scene" | "item" | "effect" | "ui" | "audio"
  status: "draft" | "generated" | "editing" | "confirmed" | "exported"
  sourcePath: string
  thumbnailPath: string
  tags: string[]
  width: number
  height: number
  format: string
  createdAt: string
  updatedAt: string
}

再配套：

GenerationRecord
EditHistory
ExportRecord
AssetVersion
ProjectConfig
5. 素材状态流

非常重要，建议内置状态机：

草稿
↓
已生成
↓
待编辑
↓
已确认
↓
已导出

这样后期可以做：

待处理素材
待导出素材
已废弃素材
最近生成素材

软件会更像专业生产流水线。

8. 最推荐的存储策略

一句话：

文件放文件夹，信息进数据库，配置进 JSON。

不要把图片塞进数据库。

SQLite 只做索引和关系管理。






明白，你问的是整个应用层面的数据管理，不是单个项目目录。

建议分成两套数据：

应用数据 App Data
项目数据 Project Data
1. 应用数据管什么

应用数据只管理“软件自身状态”：

用户设置
最近打开项目
模型 API 配置
全局素材库索引
插件配置
工具偏好
缓存
缩略图缓存
许可证/版本信息
导出预设
快捷键
窗口布局

不要把具体项目素材强绑定到应用数据库里。

2. 推荐应用数据目录

Windows 示例：

C:/Users/用户名/AppData/Roaming/PixelMaster/
├─ app.db
├─ settings.json
├─ model-providers.json
├─ recent-projects.json
├─ plugins/
├─ templates/
├─ cache/
├─ thumbnails/
├─ logs/
└─ temp/

macOS：

~/Library/Application Support/PixelMaster/
3. 应用数据库建议

应用层可以用一个 SQLite：

app.db

主要表：

projects              最近项目索引
app_settings          应用设置
model_providers       模型 API 配置
export_presets        全局导出预设
plugins               插件状态
template_library      模板库
recent_assets         最近访问素材
tasks                 后台任务记录
logs                  操作日志
4. 项目数据不要放进 app.db

项目本身应该独立：

AdventureAssets/
├─ project.json
├─ project.db
├─ assets/
├─ exports/
└─ cache/

应用的 app.db 只保存它的位置：

{
  "projectId": "p001",
  "name": "像素冒险素材库",
  "path": "D:/PixelMaster/Projects/AdventureAssets",
  "lastOpenedAt": "2026-05-28"
}
5. 为什么要这样分

这样做有几个好处：

项目可以拷贝给别人
项目可以单独备份
应用重装不影响项目
项目可迁移到其他电脑
未来支持云同步更容易
6. 最佳架构
App Database
管理软件自身

Project Database
管理单个项目内部资源

File System
存真实素材文件

也就是：

应用管入口
项目管内容
文件管实体
7. 应用首页的数据来源

首页读取的是应用数据：

最近项目列表
全局模型服务状态
最近使用工具
模板入口
软件设置

进入项目后才读取：

project.db
assets/
exports/
8. 一句话建议

你的应用数据管理应该是：

app.db 负责“我打开过什么、我怎么配置软件”
project.db 负责“这个项目里有什么素材”
文件系统负责“素材真实文件”

这个结构最稳，也最适合桌面端游戏素材流水线软件。
